# Phase 3 results

Written in P3.6. The tables below are generated by `Phase3ResultsContainerTest` (Postgres 16 and MySQL 8.4.3 in containers, SQLite in process) from the Phase 3 files `golden/<name>/phase3.forge.yml` and the translated schemas. A rule is **PASS** only when it is a rule in that file and the database says it holds on generated data; on Postgres the golden hand-written `violations_sql` is a second oracle (both must be clean), on MySQL and SQLite only our verify pass runs (the golden SQL is Postgres syntax). **Enforced by database** = a constraint the database rejects (proved by loading). **Not checked in this phase** = deferred, never PASS.

## What Phase 3 proves, and does not

Proves: statuses follow a machine with the child rows each state needs (a paid order has exactly one succeeded payment); time order against a parent holds; skew, correlation and seasonality are measurable within stated tolerances; scenarios change the mix and the burst window shows; edge-case mode loads cleanly; and generate, load and verify work on Postgres, MySQL and SQLite for events-merch and ecommerce.

Does not prove: the 23 deferred rules above; saas-multitenant (report only, not classified); Pagila on MySQL or SQLite; golden `violations_sql` on MySQL and SQLite; the LoadTest scale beyond what Phase 2 proved (no new scale run); drift, cleanup and the UI (later phases). Generated data on MySQL and SQLite uses translated schemas that differ from the Postgres ones as listed in `DIALECTS.md`.
